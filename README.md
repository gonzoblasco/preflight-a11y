# Preflight

**Your AI built the site. This proves it works — and tells the builder how to fix it.**

Preflight is a pre-launch gate for websites generated by AI tools (Lovable, v0,
Cursor, Bolt). You give it a URL. It opens the page in a real browser, checks it
against 60+ accessibility rules, then **reads it with a screen reader** and
records what the reader actually says. The report ends with a fix prompt you
paste straight back into the tool that built the page.

---

## Why this exists

Anyone can detect an accessibility bug. axe-core is free, Lighthouse ships in
Chrome, and every framework has a plugin. What none of them do is close the loop:

```
detect ──► explain to a non-developer ──► hand back an instruction the builder can execute
```

AI-built sites made the gap urgent. Someone with no accessibility training can
ship a landing page in twenty minutes, and the tools that generated it will
happily produce `<button><svg/></button>` with no accessible name. That person
will not read a WCAG success criterion. They will paste a prompt.

So the product has three layers, in order of importance:

| Layer | What it does | Why it is not a commodity |
|---|---|---|
| **Transcript** | Records what a screen reader announces, phrase by phrase, and flags every role announced without a name. | Most tools report attributes. This reports the experience, which is what the user actually has. |
| **Verdict** | One score that refuses to be green while someone is blocked. | "92/100 but checkout is unusable" is how a tool gets uninstalled. |
| **Fix prompt** | Ordered instructions, each with the announcement the reader must produce after the fix. | The acceptance line is the innovation: the builder can verify itself instead of guessing. |

## Run it

```bash
npm install
npx playwright install chromium   # or use channel: 'chrome' (default)
npm run dev                       # http://localhost:4317
```

Scan from the terminal:

```bash
npx tsx scripts/cli.ts example.com
npx tsx scripts/cli.ts https://acme.dev --min-score 90 --fail-on-blocking
npx tsx scripts/cli.ts https://acme.dev --markdown --out report.md
```

In CI, `--fail-on-blocking` is the default when `CI` is set. There is also a
composite GitHub Action in `action.yml` that posts the markdown report to the
job summary.

<summary>Example transcript, from a page with a nameless button</summary>

```
  WHAT A SCREEN READER SAYS  (virtual (Guidepup) 0.32.1)
      1  document
      2  banner
      3  heading, Ship faster, level 1
      4  image                         ← no alt: the user learns nothing
      5  button                        ← no name: the user cannot guess the action
      6  list
      7  Get started today
```

The `←` notes are generated per role by the engine, not hand-written.
</details>

## Honesty as a feature

Every report ends with a **"What this scan cannot see"** section, and it is not
hidden behind a tooltip:

- Automated checks catch roughly a third of accessibility defects.
- The transcript comes from a virtual screen reader, not VoiceOver or NVDA. It
  reflects what the DOM declares, not how a specific reader times an announcement.
- Interaction-gated content (modals, tabs, menus) is only scanned if open on load.
- Only the entered URL is scanned; links are not followed.

That section exists because a tool that overclaims gets trusted once and never
again. Preflight's whole proposition is "we tell you the truth about your page",
so it has to start by telling the truth about itself.

## Architecture

```
src/lib/
  scan.ts        Playwright + axe-core; collects the page and its findings
  narrate.ts     Virtual screen reader; produces the phrase log and gaps
  rules.ts       Rule catalog: business language, lived experience, fix recipe
  fix-prompt.ts  Builds ordered steps with acceptance announcements
  score.ts       Weighted score that cannot be green while blocking
  url-guard.ts   SSRF guard (literal host + post-DNS resolution)
  db.ts          node:sqlite; zero database dependencies
  ratelimit.ts   Burst (memory) + daily (SQLite) + license quota
src/app/
  page.tsx              Landing
  r/[id]/page.tsx       The report
  pricing/page.tsx      Plans
  api/scan              POST: scan a URL
  api/checkout          POST: Stripe Checkout session
  api/report/[id]       GET: public report JSON
```

No ORM. No component library. No CSS framework. The only runtime dependencies
are the ones doing real work: a browser, a rule engine, and a screen reader.

## Configuration

| Variable | Default | Meaning |
|---|---|---|
| `PREFLIGHT_DAILY_MAX` | `8` | Free scans per IP per day |
| `PREFLIGHT_BURST_MAX` | `3` | Scans per IP per minute |
| `PREFLIGHT_DB` | `./data/preflight.db` | SQLite file |
| `PREFLIGHT_CHANNEL` | `chrome` | Playwright browser channel |
| `PREFLIGHT_SALT` | `preflight` | Salt for IP fingerprints |
| `PREFLIGHT_HIDE_RECENT` | unset | `1` hides recent scans on the landing page |
| `STRIPE_SECRET_KEY` | unset | Enables checkout |
| `STRIPE_PRICE_PRO` / `STRIPE_PRICE_AGENCY` | unset | Stripe price ids |
